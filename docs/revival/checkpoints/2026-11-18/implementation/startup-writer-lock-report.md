# Startup writer lock — test and review report (2026-11-18)

Status: configd PR 3 and cfg PR 1 merged after exact-head CI and review. No end-to-end acceptance is claimed. The proposed password RPC must **not** hold this startup lock across configd Commit. The merged configd Commit path calls `confirmedCommitInternal`, which applies the session to RUNNING and then calls `Save`/`SaveTo`; with an outer RPC lock the nested lock wait times out after the runtime change. A real dispatcher test reproduced the 10-second timeout. An initial claim that b63160d introduced the automatic save was incorrect: its diff shows the save existed before that commit. Independent review further identified that ordinary nonfatal commit errors can skip this save while reporting a nonfatal-success string; the actual observed persistence failure still requires an appliance-level root cause test. The prior target-only design has been replaced by corrected login source; appliance validation remains pending.

configd locks local SaveTo before destination validation and snapshotting RUNNING through publication; it does not directly add a lock to Commit, although Commit invokes Save. Legacy save coordinates startup destination aliases by pinning the parent directory, comparing device/inode to the startup parent, and using the pinned directory for the temporary file, rename and fsync. Other named backup paths do not take the startup lock. Both use `/run/nudanos-startup/startup.lock`, enforce owned 0700 directory and owned regular single-link 0600 file, reject final symlinks, use bounded exclusive flock, and retain the lock inode. In production these writers must have the same privileged effective UID; the actual image's startup file is root-owned mode 0600, so non-root legacy startup saving was not established as a supported baseline behavior. The legacy archive caller uses a separate temporary backup path; the old REST named-save call path remains an identity/runtime verification item.

## Verification

- Disposable Debian helper, no host software/settings modified. The helper had only `libfile-sync-perl` installed during this work, as explicitly authorized; final Perl tests used the actual installed File::Sync without a PERL5LIB stub.
- Go lock tests: no-lock baseline failed contention and directory symlink/mode, file symlink/mode/hardlink cases; implementation passed. The full configd `GO111MODULE=off GOPATH=<private checkout>:/usr/share/gocode go test ./...` passed in the isolated test source.
- Destination validation race: the old head failed immediately when a held-lock writer had temporarily truncated the destination; the corrected head waits for the writer, validates the restored file, and saves successfully. Focused tests and the full Go suite passed.
- Save snapshot freshness: the test holds the lock, changes RUNNING with the existing lower-level session test fixture (avoiding public Commit's automatic save), releases it, and verifies that the saved file contains the new value. Temporarily moving lock acquisition after the snapshot in the disposable checkout made it fail with the old `teststring stuff`; restoring source passed. This regression verifies ordering, not the rejected outer-lock RPC design.
- Legacy `prove test/save-config.t`: 46 assertions passed using real File::Sync, including lock waiting before `cli-shell-api`, startup directory aliases, unsafe lock entries, non-root unrelated backup, real ten-second timeout, and symlink retarget race. The initial alias implementation failed two retarget assertions; using the pinned directory descriptor passed.
- Other cfg Perl files run individually: configload, system-state, template-tools and transfer-url passed. delete-addrs and load-config failed in this guest because the installed `/opt/vyatta` Config module took precedence and had no config session. rpc-reboot failed because DateTime::Format::ISO8601 was absent. These failures are environment/test setup limitations, not passing tests; the exact cfg package CI passed separately.
- Six ordered cross-language pairs of Python SavedPasswordUpdate, Go Acquire and Perl legacy save passed under a private builder-owned fixture: each holder blocked the other until release, lock inode stayed unchanged, and the Perl marker was reached at its actual configuration snapshot call. Exact Go/configd and Perl/cfg sources were used with test-only path substitution; the Python helper was the historical selective-writer implementation from e725, which was removed from the corrected read-only design. The harness cannot test the current read-only verifier. No production `/run` or `/config` paths were modified. The three accompanying `startup-writer-lock-cross-*` scripts are the exact temporary harness sources, containing only a synthetic test hash and requiring adaptation of their documented absolute guest paths before reuse. They are evidence, not packaged tests.

No ISO build or final appliance acceptance was performed for these changes. Remaining integration, original nonfatal commit diagnosis and corrected login appliance testing must be resolved before relevant merges or image work.
