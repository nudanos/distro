## Scope and package graph

Build from immutable source revisions and checksummed native sources in a clean Arch chroot. The smallest useful **authentication/configd integration slice**, not the full router closure, has this order:

1. `nudanos-vyatta-util`: source `https://github.com/nudanos/vyatta-util` at inspected trixie commit `66bbf8d4945c22d0d3e6e1e7df8d6e4a0d760080` (0.31), with native uriparser and the system C/C++ toolchain. Autoconf, automake and libtool generate its build; `make check` runs `tests/validators.sh`. Install `libvyatta-util.so.1` and development symlink/headers, plus `/opt/vyatta/sbin/{ipset-check-member,vyatta-validate-type,valid_address,local_ip}`. The library explicitly links `-luriparser`; no other non-system source dependency is declared by its build. This research snapshot is not proof of the revision in the eventual validated Debian image; pin the image's actual resolved source.
2. `nudanos-vyatta-cfg`: build against that library, Jansson, uriparser, Perl and Python; provide `libvyatta-config`, its headers, the Python `vyatta.configd` binding, Perl `Vyatta::Configd` binding, and legacy Cstore compatibility library/bindings. Full existing build additionally invokes autotools/libtool, pkgconf, flex, bison, SWIG, CppUTest, doxygen, cpio and chrpath. Avoid deleting compatibility outputs merely to reduce dependencies. Native Perl and Python import paths must work in addition to preserving `/opt/vyatta` conventions. Debian control and Makefile are the baseline for exact artifacts.
3. `nudanos-configd`: native Go/CGO and audit, with immutable source graph for danos/config, encoding/rfc7951, mgmterror, utils, VCI, yang, dbus, fsnotify, go-systemd, x/crypto and their transitive imports. Derive the complete graph from the pinned source with offline Go tooling; the listed direct Debian Build-Depends alone are not a complete lock. Include configd, yangd and config/yang utilities and model files required by the selected installed functionality. Do not treat the passing standalone binary as an integrated service.
4. `nudanos-login`: links real `libvyatta-config`, `libvyatta-util`, Jansson and PAM; runtime includes Python, Arch `python-crypt_r`, the Python and Perl cfgclient bindings, Perl IPC::Run3, JSON, Template and NetAddr::IP, plus actual account, password quality and password hash tools used by installed scripts. Map exact package providers in the clean chroot, not guessed Debian package names. Stage YANG, templates, scripts, renewal PAM module and Perl helpers. Preserve the public RPC and on-disk hash formats. Package `pam_vyatta_passwd.so` under `/usr/lib/security` and establish an Arch renewal stack before claiming renewal support.
5. `nudanos-cli-sandbox`: build against PAM and libsystemd; runtime Python/PyYAML, systemd-nspawn/machined and the existing scripts, units, templates, hooks and PAM module. Package isolation as an optional feature, because the current Debian root builder dependency `mmdebstrap` is not an Arch root filesystem. An Arch-built root with `/bin/vbash`, renewal module and required assets is an additional prerequisite, not a download of a Debian image. Until root provisioning and PAM session integration are proven, reject isolation activation.
6. `nudanos-arch-integration`: own Arch-specific PAM integration and explicit sysusers/tmpfiles/systemd assets; do not install `vyatta-debian-pam-configs-config` or run its dpkg diversion scripts. Group the packages however needed to prevent file ownership overlap; their semantic boundaries matter more than package names.

The full Task 8 CLI, VCI, interfaces, VRFs, static routes and FRR closure additionally requires provisiond, `lu`, CLI/op shell, model providers, D-Bus and network components. `configd/debian/control` explicitly depends on cli-shell-api, lu, provisiond and yangd; its service invokes `/opt/vyatta/sbin/lu` and uses `configd`, `vyattacfg`, `vyattasu`, and `/var/run/vyatta/configd`. This document does not assert a complete router closure until the Debian image manifest and native build graph are reconciled. Provider versions and Arch package availability must be validated during implementation, not inferred from names here.

## Shared build and runtime contract

- Provide ordinary build, check and `DESTDIR` install targets for each product. No package build may edit live PAM, accounts, run directories, or start services. Preserve Debian's install split, executable modes, sonames, supported imports, `/opt/vyatta` script/template paths and `/usr/share/configd/yang` models. Compare staged file lists, contents and package ownership with the validated Debian build. Debian's existing multiarch PAM override must keep working; Arch sets `/usr/lib/security` explicitly.
- `vyatta-cfg` currently hardcodes `/usr/lib/python3/dist-packages/vyatta` and `/opt/vyatta/share/perl5`, generates SWIG bindings, uses `chrpath` on generated artifacts, and unconditionally generates docs. Parameterize Python's actual site-packages and Perl install path, honoring DESTDIR while retaining `vyatta.configd`, `Vyatta::Configd`, legacy `Vyatta::Config` and Cstore identities; do not rely on Debian dist-packages on Arch. Verify ABI, `ldd`, Python and Perl imports against real libraries, not fixture headers. Keep legacy config and persisted state intact. Handle static-link assumptions and toolchain incompatibilities based on observed native build failures, not preemptive removal of flags.
- Reproduce `dh-yang` and `dh-vci` outputs as ordinary, deterministic build/install assets: inspect actual Debian package contents and trigger effects, install corresponding models, component metadata and D-Bus policy with their runtime users; do not merely copy `.yang` files. Pin Go modules or an immutable vendor/GOPATH snapshot for the whole daemon/plugin graph without changing supported import identities; prove offline builds and compare outputs. The earlier Go build staged Debian source snapshots but built native objects; it is not a lock.
- Define ownership and creation for service users/groups, sockets and runtime directories, required capabilities and unit ordering. Debian postinst creates `secrets` and configd user/group and grants `cap_audit_control` to the binary; the unit launches via `lu` with explicit socket/run paths. Implement equivalent least-privilege behavior only after checking `lu`, VCI and model provider requirements. Test actual peer credentials and running services. Ensure upgrades retain config, administrator edits, users and persistent data; removal must not silently erase them.

## Arch PAM adapter

PAM is an explicit distribution boundary. Keep Debian `pam-auth-update` and dpkg implementations intact and dispatch to an Arch adapter only on supported Arch. The Arch guest's stock `system-auth` passed isolated local faillock tests, but its actual effective service stacks and package revisions must be inspected on each supported baseline. `faillock` executable path on Arch differs from the hardcoded Debian `/usr/sbin/faillock`; resolve through a platform contract, not a blanket replacement.

Use narrowly owned Arch fragments/configuration and a controlled, reversible integration into recognized effective PAM stacks. Pacman must not own or overwrite pambase's files or replace administrator customizations. Since PAM inclusion, control jumps and service overrides affect security, preflight must inspect effective `/etc/pam.d` overrides and `/usr/lib/pam.d` fallbacks for console and installed SSH paths, reject unknown or bypassing stacks and symlinks, check module/tool availability and establish recovery before activation. Stage atomic changes, verify effective rules and rollback on error; no implicit activation during build or package installation. An adapter may edit a recognized stock stack only with exact ownership markers and safe compare/restore; avoid overwriting independently edited files. Retain an out-of-band root console throughout tests.

- Lockout: preserve existing configured attempts and unlock seconds, local-only restriction, root exemption, reset/read semantics, `/run/vyatta-faillock` and fail-closed behavior. Ensure authfail, authsucc and jump ordering actually enforce the threshold and reset; stock Arch `system-auth` already contains faillock rules, so detect and reconcile rather than add a second independent counter. Reject mixed RADIUS/TACACS or unknown stacks as Debian does. Migrate only an exactly recognized owned legacy stack and preserve unsupported legacy state for administrator review.
- Password renewal: integrate `pam_vyatta_passwd.so` into the effective password stack with native PAM and verified control flow; preserve existing hashes, accounts and RPC identity. Do not transplant Debian's `common-password` profile or dpkg diversions. Activation, rollback and safe removal must verify that no effective service still refers to the module and that a working password path remains.
- Isolation: integrate required session rule only after verifying login/SSH inclusion and no control-flow bypass, module presence, units and an independently provisioned root. Preserve the current fail-closed activation and disable checks. Check all effective service references before removing the module, and leave administrator-owned modifications untouched. `pam-sandbox-check` already scans both `/etc/pam.d` and `/usr/lib/pam.d`, but its Debian common-session exclusion must be generalized carefully.

Pacman scriptlets cannot be assumed to abort or roll back transactions safely. Perform explicit preflight and safe deactivation before removal/upgrade, and design packaging so an active PAM reference never points to a removed module even when transaction hooks fail. Prove this with actual pacman transactions before choosing final lifecycle mechanics; do not depend solely on a failing pre-remove scriptlet.

## Source and runtime dependency evidence

`vyatta-util` was cloned for research into `implementation/arch-source-research/vyatta-util`; its checked out HEAD is `66bbf8d4945c22d0d3e6e1e7df8d6e4a0d760080` (commit 2026-10-21). Its `debian/control`, `debian/rules`, `configure.ac`, `Makefile.am` and `debian/*.install` give the package contract above. The Debian build uses `--prefix=/opt/vyatta --libdir=/usr/lib --includedir=/usr/include` and `-Wl,-z,defs`. Its check target runs validator exit-status fixtures; no Linux build or package was attempted here. Validate the source library's `1:0:0` libtool version and runtime tools in an actual native staged build.

The current distro manifest uses `kind: danos`, `ready: true`, `ref: trixie` for util, cfg, configd, login, sandbox, VCI, provisiond, ifmgrd, op and other product sources. Fetch resolves remote branch heads and detaches at the resolved commit; therefore this manifest alone is not an immutable source lock. It also permits a full SHA as ref. Retain each exact validated image source and version, as well as upstream and Go transitive sources, before a reproducible Arch release. The manifest's `yangd` entry is a separate later-milestone repo; the required Debian `yangd` binary is built by the configd source package, so do not confuse its namesake entry with the installed daemon.

Concrete additional product sources implied by existing package/runtime contracts for the integrated slice:

- `lu` (manifest `nudanos/lu`, trixie): configd and ifmgrd units use it for identity transition; inspect its package and privilege contract.
- `vci` (private D-Bus, component helper and policy), `ephemerad` and `notifyd`: Debian `vyatta-vci-bus` depends on the latter two plus D-Bus. Include their native daemons, policies, component metadata and required Go sources; separate build-only generators from runtime assets. `provisiond` handles legacy non-VCI configuration.
- `opd`, `op`, `aaa`, `vyatta-bash` and cfg/config-utils artifacts for operational and configuration shells; `vyatta-op-shell` depends on `opc`, and opd depends on `lu`. Stock bash is a Debian alternative, while sandbox preflight requires `/var/lib/sandbox/bin/vbash`.
- `ifmgrd`, `vyatta-interfaces`, `routing-instance`, `vrf-manager`, `vyatta-kernel-forwarding`, and their models/helpers for interface and VRF acceptance. Control files identify `ifmgrd` to `lu` and its YANG modules; `routing-instance` to Python VCI, vrf-manager, vyatta-cfg and vyatta-system; vrf-manager to iproute2, legacy config Perl binding and a VRF-capable kernel/forwarding provider. Preserve kernel capability checks.
- `vyatta-protocols-frr`, `vyatta-protocols-common` and FRR (including FRR Python tools and selected VCI/YANG route providers) for static routing. Resolve the subset required by the selected static-route model from the validated image and installed metadata. Verify Arch FRR compatibility.

These are evidenced direct dependencies and source families, not a claim that every transitive package has been enumerated. Model-generated `${yang:Depends}`, service metadata, Perl/Python module providers and full Go imports require offline resolution against the selected Debian image and clean Arch package graph. No source should be omitted merely because a daemon builds standalone.
