## Provider contracts that implementation must preserve

- `lu` candidate `source/lu.c` writes `/proc/self/loginuid` with `O_NOFOLLOW`, resolves the named user and `execvp`s the target. It changes supplementary groups and real/effective/saved GID and UID **only with `--setprivs`**. Debian configd unit and provisiond component use `-user configd` without that flag. Thus treating `lu` as automatically dropping privileges is incorrect. Preserve the current tested identity semantics first; verify actual audit loginuid, peer credentials and privilege/capability requirements under systemd. Any change to privilege model needs its own tested security design, not an incidental packaging substitution. Its Makefile supports `PREFIX` and `DESTDIR`; install `/opt/vyatta/sbin/lu`.
- Candidate VCI ships private `vyatta-vci-bus.socket` at `/var/run/vci/vci_bus_socket`, `dbus-daemon` unit and `vcidbus/vyatta-vci-bus.conf`, `messagebus` user, EXTERNAL credentials and deny-by-default name/method policy. Keep those boundaries and the systemd activation, path and generated service policy on Arch. `deb-vci-helper` reads `/lib/vci/components/*.component`, generates systemd units/aliases, D-Bus activation files and `/etc/vci/bus.d/*.conf`; its install path also interacts with live systemd. Extract a deterministic offline generation interface from `vci/conf` and `deb-vci-helper` rather than executing a live service manager during `package()`. Confirm any `/lib` to `/usr/lib` compatibility.
- `provisiond/debian/provisiond.component` names `net.vyatta.vci.config.provisiond`, invokes `/opt/vyatta/sbin/lu -user configd /usr/sbin/provisiond`, reads `/etc/vyatta/provisiond.conf`, and declares `DefaultComponent=true`, model set `vyatta-v1`. Package its component, generated activation metadata and config, not merely the Go executable. Candidate depends on `deb-vci-helper`; VCI bus also depends on ephemerad and notifyd. Preserve their components and model metadata where the selected model set requires them.
- `configd/debian/yangd.component` invokes `/usr/bin/configd` for `yangd-v1`; Debian `configd.service` separately invokes `/usr/sbin/configd` with configured Unix socket and runfile. Confirm actual Debian staged binaries, symlinks, component and service output rather than assume these two paths are interchangeable. Configd requires cli-shell-api and `yangd`; root-owned socket and credential authorization must be verified in a real service session.

## Execution tasks, in dependency order

1. **Freeze evidence and package graph** — in `distro` and an Arch packaging workspace, record candidate `Release`, `Packages`, `Sources`, package/arch checksums and exact post-gate source commits including four merged PR heads. Build an offline source lock for the Go `Built-Using` graph and generators (`dh-yang`, `dh-vci`), resolve real Arch package providers, and preserve the candidate's dependency alternatives and model relationships. Establish full YANG import closure for the chosen supported behavior, including TACACS references. Test missing/mismatched source and missing model failure. No `.deb` extraction as runtime payload.
2. **Shared C and binding stage** — use `vyatta-util/{Makefile.am,configure.ac}` and `vyatta-cfg/{Makefile.am,configure.ac,perl_dmod/Makefile.am}` in isolated worktrees. Add normal build/check/staged install interfaces only where necessary, parameterizing cfg Python site-packages and Perl module location, leaving Debian defaults/sonames and `/opt/vyatta` unchanged. Build util then cfg with native uriparser, Jansson, Python, Perl, SWIG, flex/bison and CppUTest. Compare Debian `debian/*.install` manifests including legacy Cstore, use actual linked libraries and check Python `vyatta.configd`, Perl `Vyatta::Configd`/legacy imports, ABI and executable paths. Run Debian existing tests and manifest comparison after each shared change.
3. **VCI/provider stage** — `vci/{conf,deb-vci-helper,vcidbus,debian}`: expose deterministic file generation without live systemd; package bus policy, socket/unit and component metadata; use `provisiond/{debian/provisiond.component,cmd/provisiond}` and source `lu/{Makefile,source/lu.c}`. Build Go components offline from locked source. Compare generated unit, aliases, D-Bus activation and policy with candidate binary packages, and verify policy ownership and unauthorized method/name denial. Create required runtime users/groups/directories via appropriate Arch package assets while preserving existing identities and admin files. Verify audit loginuid and actual process IDs, not inferred privilege drops.
4. **Configd/YANG stage** — `configd/{cmd,client,rpc,debian/*.component,debian/*.service,debian/*.install}`: ordinary offline build/check/install for configd, yangd, config-utils, yang-utils and models; use generated component metadata from task 3. Explicitly stage `/usr/bin` and `/usr/sbin` behavior shown by candidate packages and paths in `.component`; do not assume. Add the `cli-shell-api` executable and its cfg runtime requirements, model assets, plus provisiond and bus. Preserve socket/runfile, ACL, `secrets`, `vyattacfg`/`vyattasu`, ownership and capability semantics. Run Go tests and Debian regression suite, then native service startup, valid/invalid peer and persisted config/restart tests in disposable VM.
5. **Auth and platform adapter** — `vyatta-login/{Makefile.am,src/Makefile,lib/Vyatta/Login/Faillock.pm,scripts,debian}` plus new Arch-specific adapter/package assets. Keep existing Debian behavior; dispatch by supported platform. Link `pam_vyatta_passwd.so` against real cfg/util, Jansson and PAM; native Python `crypt_r` and cfgclient must run without fixtures. Test real configd RPC as the target effective identity, legacy hashes, Unicode, invalid/expired credentials and password renewal. Implement recognized Arch effective PAM auth/password stack integration, local-only faillock and root recovery using private tally path; refuse unknown/admin-modified stacks and test atomic rollback and package lifecycle before enabling.
6. **Sandbox** — `cli-sandbox/{Makefile,lib,src/pam_sandbox,tmplscripts/system/login/user_isolation.sh,scripts,conf,debian}`: preserve Debian `pam-auth-update` path; add Arch session adapter only once validated Arch nspawn root and `vbash`/renewal assets exist. Package Python/PyYAML, systemd-nspawn, module, units and hooks. Verify control flow in login and SSH, module paths, root bind requirements, disabled/upgrade states, reference-safe removal and admin edits. Run live sandbox login and recovery tests; otherwise activation remains explicitly unsupported.
7. **Native transaction and regression gate** — clean Arch chroot builds signed/checksummed native packages and rejects missing inputs; install/configure/save/reboot/upgrade/remove/reinstall in disposable native VM with out-of-band console. Assert no account/config/tally/legacy data loss, no dangling PAM modules or security-policy bypass, package ownership and recovery, real RPC and generated VCI paths. Run Debian staged manifest and functional regression tests again. Save package/source manifests, commands, exit statuses and test logs; do not label stage complete before all acceptance tests pass.
