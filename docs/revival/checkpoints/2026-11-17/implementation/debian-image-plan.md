# Debian candidate image implementation plan

**Goal:** Build and locally verify a Debian 13 NuDanOS image containing the four merged changes, with a preserved pre-change upgrade fixture and auditable inputs.

**Architecture:** Use the disposable Debian QEMU guest on port 2222 and a new case-sensitive guest work directory. Resolve source commits once, use an isolated manifest and a local test-only archive key, build a signed local package repository and ISO, then exercise real appliance lifecycle flows. Preserve the existing baseline repository separately. Never run the nightly workflow or publish artifacts.

**Tech stack:** Debian 13, distro-build, Go 1.26, rootful Docker or Podman, live-build, QEMU TCG, GnuPG, systemd-nspawn and APT.

**Reference:** `implementation/linux-environment-report.md`, `implementation/task-3-report.md`, `distro/README.md` and `distro/.github/workflows/nightly.yml` (verify actual workflow filename in the selected checkout).

## Constraints and evidence

- Wait for the four merged SHAs from the root agent before building the candidate; verify each is the intended merged commit and reachable on its target branch. Do not assume the PR tip is the merge result.
- Use a clean isolated distro checkout at the selected distro SHA; do not touch the dirty `nudanos-revival/distro` index or its safety fixture changes. Guest source and work directories must be fresh: `fetch.Git` forcibly checks out and cleans its work tree.
- The default manifest follows moving `trixie` branches. Resolve and record every ready DANOS ref once, pin all of them to full commit IDs in a separate manifest, and record upstream tag/packaging revisions, apt package versions, source hashes, builder digest, distro SHA, exact commands and build logs. Set the four named packages to the supplied merged commits and verify actual built trees and package metadata. If a required commit is unreachable in the normal fetch, fetch it explicitly into the isolated checkout and verify it before build.
- Fixed source SHAs alone do not provide bit reproducibility: Debian mirrors, Docker base images and live-build install packages are mutable. Record resolved versions and checksums; retain local inputs, and use a dated snapshot or retained repository if available. Report any remaining unpinned inputs explicitly.
- Baseline archive `test-runtime/downloads/nudanos-debian-baseline-apt-repo.zip` is retained unchanged; verify its signature using the committed archive public key, record archive digest and versions, and copy it to a separate read-only fixture. It is an old package repository, not proof that a bootable baseline ISO or appliance exists. Locate a matching older ISO or create a baseline ISO from verified old inputs; never describe a synthetic dpkg fixture as a full appliance upgrade.
- The supplied distro image command requires a signed `work/repo` and privileged container; `image/make-image.sh` installs live-build, serves the repository, and embeds the repository public key. Generate a dedicated disposable local signing key and use its actual fingerprint with `-gnupg` and `-key`; do not use or upload release credentials. Confirm the generated repo signature and the embedded key match. Preserve the CI-key-signed baseline separately.
- Existing runner selects the lexicographically newest ISO under `work/image`; place only the candidate in its candidate work directory and verify its SHA256 before every runner invocation. Capture output, version listings and logs without real credentials. The builder guest uses TCG; appliance acceptance is owned separately on native Windows QEMU, avoiding nested QEMU. Both workloads may be slow under software emulation.

## Tasks and acceptance checks

1. **Prepare guest and baseline.** Check host and guest disk capacity; enlarge sparse guest storage or add a workspace-local disk if needed. Install and start a rootful container engine and systemd-container only inside the disposable guest, verify `docker info`/equivalent, privileged loop mounts and nested QEMU feasibility, and retain package/version logs. Verify and inventory the signed baseline archive and locate a real baseline ISO or installed disk. Do not overwrite the archive or existing guest fixtures.
2. **Lock sources and build candidate.** After receiving merged SHAs, create isolated distro checkout and source lock; verify clean source and exact identities. Build `distro-build`, run `builder`, `plan`, `build`, `repo`, then `image` with explicit manifest/work/key paths. Reuse verified CI packages only when exact source/build inputs and required package versions are established; otherwise rebuild the dependency closure and record its provenance. Verify APT index signature, package versions and SHA256, ISO digest, and embedded package version list. Ensure upgrade candidates compare newer than baseline with `dpkg --compare-versions` before claiming an upgrade.
3. **Fresh install and boot.** Run `test install` and full `test boot`, retaining serial transcript and exit statuses. The boot runner exercises a disk install, rejects the live default password and reboots; inspect its exact assertions and add separate lifecycle probes for anything not covered. Boot a clean candidate, perform a real fresh installation and login on its installed disk; confirm expected package versions, configuration and services after reboot.
4. **Real upgrade.** Boot an authentic preserved old appliance disk/image, capture baseline versions, config, password and PAM state, then install/upgrade through APT against the locally signed candidate repository and reboot. Verify dependency resolution, `dpkg --audit`, ownership transfer, admin-owned PAM configuration preservation, login and service health. Keep an untouched baseline disk and run destructive steps on a copy/overlay. If no authentic old image can be obtained, report the upgrade gate blocked and retain separate namespace/dpkg fixture results without calling them a full upgrade.
5. **Password renewal, lockout and sandbox.** On installed candidate and upgraded appliance, drive real user password renewal through the deployed PAM/configd path, verify old password refusal and new password login after reboot; test consecutive-failure lockout, legitimate reset and root recovery with fixture credentials. Enable user isolation and exercise an actual nspawn-backed login/session, verify expected user identity, boundaries and clean session teardown; confirm disable/re-enable and package state. Capture redacted logs, PAM stack and command exit codes. Distinguish unsupported prerequisites or failed tests from passes.
6. **Record result.** Save source lock, package versions, signature verification, image checksum, commands, timestamps, VM resource settings and redacted transcripts in `implementation/`. Report all gates individually and preserve the candidate and upgrade fixture locally. No releases, workflow dispatches, secrets, or host setting changes.

## Approved controlled-pool route (2026-11-08)

Use the signed November 3 baseline package repository and ISO identified in `implementation/debian-baseline-provenance.md`. Preserve both unchanged. On a separate pool copy, enumerate all binary packages by their `Source` control field (including split binaries and implicit source names), and all source files by the signed Sources index. Remove every artifact belonging to the four changing source packages, add all newly built outputs from the exact merged source commits, and verify no stale versions or duplicate package/version pairs remain. Build in the distro builder with the baseline pool indexed for dependencies; capture source commits, tree hashes, package build logs and outputs. Record unchanged packages by their signed baseline artifact and checksums; their moving branch source SHAs are unknown unless separately proven. Run the existing `builder/make-repo.sh` with this complete pool and a new throwaway signing key in a fresh candidate directory, then verify `InRelease`, Packages and Sources indices and payload digests. Verify Debian version ordering and candidate output ownership, dependencies and split-package relationships, particularly login/renewal and configd. The candidate public key must be explicitly installed in the disposable old appliance before its APT upgrade. Export the complete signed repository and public key to the acceptance operator. Build the ISO from this repository using the same isolated builder and image configuration. Do not confuse a local test key with the release signing key.
