## Rejected 1.0~20261109.1 diagnostic image

The image build completed and its SHA256 was `41f9a41f251a371f6c4ce883bde5b4c8c6d08c96850ba7679ef7875c86a3b2b3`, with embedded image ID `1.0-20261109.1.1257`. It is rejected for security-sensitive ownership defects and must not be used for acceptance: `/usr/bin/chage`, `/usr/bin/expiry`, `/usr/sbin/unix_chkpwd` and `/usr/bin/crontab` were mode 2755 with group root rather than the baseline shadow or crontab group. Root `/`, `/etc`, `/usr`, passwd and sudo modes checked correctly; an empty dpkg audit alone did not detect the group corruption.

The defect was traced to the reused bootstrap filesystem cache. A separate disposable container probe created a 0:42 mode 2755 file; `sudo docker cp -a` to the guest produced 0:0 mode 2755 in this environment. The 317 MiB copied bootstrap filesystem is unsafe and must never be reused. Future builds use only downloaded package caches and fresh debootstrap, with `verify-image-bootstrap.sh` checking root ownership and expected shadow/crontab groups for the setgid binaries and recording every setuid/setgid file before full image construction. Independently compare full final squashfs setuid/setgid and capability inventories with baseline, verify root directory/file modes and package audit, and withhold handoff on any unexplained mismatch. No recursive rootfs ownership repair is permitted.
