### November 26 update

Candidate `1.0~20261118.2` contained both manifests. Final verification found that xorriso patched the GRUB El Torito boot file after live-build computed its checksum. The updated [checksum PR](https://github.com/nudanos/distro/pull/2) generates both manifests in the binary hook and excludes that one file. The externally recorded SHA-256 covers the complete ISO. A fixture test confirmed that both manifests accept the patched boot file and reject an altered live filesystem. GitHub CI passed for the revised commit.

The first `1.0~20261118.3` build stopped during bootstrap when its builder went offline. The resumed build starts with a fresh bootstrap, the same signed package inputs and a package-download cache. The preserved October appliance is ready for the normal image upgrade once the replacement ISO passes both manifest checks.

The upgraded Debian guest also created a fresh optional sandbox root with renewal 2.46. A real serial login used a distinct mount namespace and root filesystem, could not see the host marker, and used `/dev/ttyS0` as its terminal. The terminal alias was root-owned and mode `000`, and the isolated user could not read it by path. The separate legacy sandbox test is in progress.

The resumed `1.0~20261118.3` build completed. Both internal manifests and the repeated package, setuid/setgid, capability and ownership audit passed. The external SHA-256 is `67c98041330efd7a6d65cc645bbfdfa1ce130e91b1faed6e9d7283e1b2388211`. The October appliance accepted the ISO's MD5 manifest and copied the image. Its installer reported GRUB errors before printing `Done.`, so that run failed the upgrade check.

The legacy host took the signed package upgrade while retaining the old sandbox package database. Its serial login entered the old root, used renewal 2.43 inside it and loaded the same PAM module as the upgraded 2.46 host. Renewal reported a partial failure. The boot-loader hook failed because `/boot/grub` was absent, and configd skipped the save after changing the active password. The saved-password verifier confirmed the discrepancy. This explains the legacy test failure. The evidence does not identify the cause of the earlier separate interim fixture.

The boot mount generator writes its files outside the systemd generator directory. [Image tools PR 1](https://github.com/nudanos/vyatta-image-tools/pull/1) corrects the output location. The regression test passed. A daemon reload in the legacy fixture loaded the corrected unit from `/run/systemd/generator` and pointed it at the existing GRUB directory. The cold boot, live renewal and normal image upgrade are being retried with the fix.
