## Historical selective-writer checkpoint

The earlier selective-writer login checkpoint `e725440` is historical and must not be merged. Public configd Commit calls Save on ordinary success, so holding its proposed outer startup lock across Commit causes a nested timeout after RUNNING changes. The earlier raw-Commit/unsaved-state assumption was false. Ordinary nonfatal commit errors can instead apply RUNNING, skip Save and return a warning; this is a possible explanation for the old failure, not an established appliance attribution. The historical reboot-failure fixture is preserved.

Earlier isolated tests of the selective design did not capture configd's automatic save and are not end-to-end proof. The corrected source and evidence are recorded in the developing [November 18 checkpoint](checkpoints/2026-11-18/README.md). The [November 17 checkpoint](checkpoints/2026-11-17/README.md) remains an unchanged historical record.
